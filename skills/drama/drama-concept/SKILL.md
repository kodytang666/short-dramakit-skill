# 短剧选题与项目立项

把一个点子或一部小说变成**有证据、有风险登记、可交接**的立项决策。本技能是短剧制作流水线的第一站：回答"这个项目值不值得做、能不能做、按什么规模做"，然后把结论固化成三份文档交给故事开发阶段。

## 核心立场

1. **评估先于创作**：未通过评估的选题进入开发，浪费的是后续六个阶段的成本。
2. **证据分级**：所有判断必须标注证据强度——`[实测]`（用户提供的真实数据、原文证据或小样本验证）、`[官方]`（平台/厂商官方文档转述，有来源与核对日期）、`[推断]`（从证据合理推导）、`[待验证]`（行业通识但当前无法核实）。裸断言不合格。
3. **不脑补**：只有书名时拒绝凭记忆推断内容（吸收自成熟原著分析方法论）；市场数据缺失时如实标注，不编造平台政策与数字。
4. **创作者拍板**：评估给建议，立项由创作者确认；停靠点不可跳过。
5. **配方不是门槛**：题材规律是参考判断项（craft），不是硬性检查项；创作者说明理由后可覆盖。

## 入口分流

| 入口 | 判断条件 | 动作 |
|---|---|---|
| A 原创点子 | 用户提供一段创意描述（无原著） | 走六维评估，第④维用"原创可开发性六问" |
| B 小说 IP | 用户提供书名+简介，或原文 | 走六维评估，第④维用"IP 适配评估"（含四类判定） |
| C 续跑 | 项目目录里已有选题评估报告 | 读报告，从断点继续，不重跑已完成维度 |

只有书名、无简介无原文：**不启动评估**。请创作者提供简介或原文——凭书名回忆情节会产出无法追溯的伪证据。

## 信息采集（一次问全）

评估前确认以下参数。缺失的**一次性**问全，不轮流盘问；创作者未给且能合理建议的，给出建议值并标注 `[待验证]`；问过之后创作者仍未提供（沉默/明确不给）时按建议值继续并在报告中声明"建议值，创作者未确认"：

- **必要**：目标平台倾向（付费卡点 / 免费投流 / 未定）→ 决定商业模式初判方向；集数 × 单集时长（竖屏短剧常见 60-100 集 × 1-2 分钟或 20-40 集 × 2-3 分钟，按题材给建议）。
- **B 入口专用**：能否提供原文全文（决定走全量、抽样还是"简介+梗概"降级评估，见 ip-evaluation.md）。
- **可选**：预算量级、对标作品、创作者不可改约束（必须保留的人物/结局/题材元素）、内容尺度边界。

## 六维评估

每一维的产出固定三行字段，写入选题评估报告（模板见 [templates/topic-report.md](templates/topic-report.md)）：

```markdown
### ② 受众与市场
- 结论：……
- 证据：……
- 强度：[实测|推断|待验证]
```

### ① 题材定位

读 [references/genre-cards.md](references/genre-cards.md)。选题场景可同时取 2-3 张题材卡横向对比（这与故事开发阶段"一次一张"不同——立项需要比较）。输出：题材归类（可多题材混合）、命中桥段、同质化程度判断（该题材桥段的辨识度过高时是风险也是机会）。

### ② 受众与市场

按 [references/market-method.md](references/market-method.md) 产出受众画像卡：**谁在看**（人群/性别比/观看场景）、**来感受什么**（情绪需求：爽/甜/燃/恨/悬念）、**什么时候走**（弃剧点）。市场部分只做定性判断与对标（创作者提供了对标作品时），不编造平台数据。

### ③ 爽点与情绪价值

- 爽点类型识别（对照题材卡的爽点字段与桥段表）；
- 爽点密度潜力：该题材常规每集可兑现的爽点频次量级；
- **开场钩子潜力**：收益最强点在哪、能否做成第 1 集开场（冷开候选）、观众必须后补的信息是否足够少。

### ④ IP 适配（B 入口）/ 原创可开发性（A 入口）

- B 入口：按 [references/ip-evaluation.md](references/ip-evaluation.md) 做四类判定（`screen_ready` / `needs_carrier` / `prose_only` / `ai_hard`），写比例与分母；长篇按抽样法，报告首行写覆盖率。
- A 入口：原创可开发性六问——(1) 观众主要来吃什么（爽点/甜点/情绪价值是否明确）；(2) 卖点与异常局面是否亮（谁+异常局面+必须做什么+最抓人的点）；(3) 主角眼前的麻烦是否成立（不动会失去什么）；(4) 追看引擎能否持续（升级/调查/身份反打/关系拉扯/倒计时，能推多少集）；(5) 体量是否匹配目标集数（阶段性变化够不够切）；(6) 能否压成一句话 hook。

### ⑤ AI 制作可行性

按 [references/ai-feasibility.md](references/ai-feasibility.md) 评五维，每维给 低/中/高 负担评级 + 一句依据：

1. 角色一致性难度（主角数 × 造型变化频率 × 跨集出场）
2. 场景复用度（不重复场景数与参考图复用性）
3. 动作与特效复杂度（打斗/肢体接触/特效量）
4. 画面文字依赖度（系统面板/手机屏幕等文字密集桥段）
5. 镜头量级（集数 × 每集镜头密度 → 总镜头量级，决定生成成本与周期）

### ⑥ 规模与风险

- 规模建议：集数 × 单集时长 × 预估总镜头量级（与⑤联动）；
- 风险登记（`RSK-` 编号）：每条含风险描述 / 类型（商业|制作|内容）/ 影响 / 缓解措施。**至少 3 条，且制作类与商业类都不得缺席**。

## 候选比较（多方向时）

方向未定或点子可走向多个机制时，做**机制不同**的候选对比表（换主角策略/对抗来源/代价结构，不是换标题换职业）。每个候选评八要素：戏剧承诺、主角追求、对抗机制、反复回报、可升级状态、长线终止条件、主要制作负担、商业潜力。至少 2 个候选才构成比较；凑不出机制差异就不硬造。

## 停靠：立项决策

六维评估完成 → 向创作者汇报：**总评建议**（立项 / 调整后立项 / 放弃）+ 一句话理由 + 最关键的 1-2 个风险。**停下等待确认**。

- 确认立项 → 写项目立项书 + 制作简报（下节）。
- 调整后立项 → 记录调整决策（`DEC-` 编号），重跑受影响维度，再停靠。
- 放弃 → 不写立项书；写简短放弃报告（结论 + 理由 + 何种条件下可重启），流程终止。
- 创作者事先声明"一次跑完不停" → 跳过停靠，但评估报告照常产出，立项决策记录标注"未停靠自动立项"。
- 多候选场景：总评停靠时同时请创作者在 `CAND-` 候选中选择或组合方向；候选选择本身记一条 DEC 决策。
- 某一维信息不足时（问过仍缺）：该维结论如实写"信息不足，无法判定"并给出需要补什么信息——**不许用编造内容凑数**；"信息不足"超过两维时建议补齐后再评估。

## 立项文档

按模板写两份（模板字段不得删除，可加不可减）：

1. **项目立项书**（[templates/project-charter.md](templates/project-charter.md)）：定位一句话、核心卖点（≤3 条，每条绑定一个爽点类型）、受众画像卡、规模参数、商业模式初判（`[待验证]`）、风险登记表、决策记录、审批区。
2. **制作简报**（[templates/production-brief.md](templates/production-brief.md)）——**阶段一 → 阶段二的唯一交接文档**：已定事实（不可改，来自创作者约束与已确认决策）/ 可探索空间 / 边界约束三区分离；附题材卡要点、受众与爽点要点、制作可行性预警（下游提前规避的高负担项）。

立项书与评估报告的结论必须一致：评估说"调整后立项"，立项书里必须体现调整后的方向与对应的 DEC 决策。

## 编号与版本

- 项目 ID：`PRJ-<slug>`（立项时生成，全流水线复用）；候选：`CAND-1…`；风险：`RSK-1…`；决策：`DEC-1…`。
- 三份文档头部统一 frontmatter：`project_id / doc_type / version / date / status: draft|pending|approved`；评估报告另有 `入口类型` 字段（A/B/C）。
- 模板中标注"（B 入口必含）/（A 入口必含）"的条件字段按实际入口取舍：A 入口删去 B 专用行、B 入口删去 A 专用行，其余字段可加不可减。
- 上游修改传播：立项书的规模参数（集数×时长）变更 → 简报 version+1 并在变更记录中注明；下游以最新简报为准。

## 自检清单（成稿前逐条核对，不通过不交付）

1. 六维齐全，每维三行字段（结论/证据/强度）完整；
2. IP 入口含四类判定比例与分母，报告首行有覆盖率声明（抽样时）；
3. 市场与平台类论断全部带强度标注，无裸断言；
4. 风险 ≥3 条，制作类与商业类齐备；
5. 立项书结论与评估报告一致；卖点每条绑定爽点类型；
6. 简报三区分离，已定事实均有出处（创作者输入或 DEC 决策）；
7. 无编造：未获得的平台数据、模型能力声明一律 `[待验证]`；
8. 模板字段无缺失（可加不可减）。

## 常见错误与纠正

| 错误 | 纠正 |
|---|---|
| 凭书名脑补剧情 | 拒绝启动，索要简介或原文 |
| 六维只有结论没有证据 | 每维必须回到输入材料或题材卡找证据 |
| 风险栏写"改编难度较大"这类空话 | 风险必须具体到哪个维度、哪个桥段、什么影响 |
| 把题材规律当硬门槛（"战神必须 80 集"） | 题材规律是 craft 参考，创作者约束优先 |
| 市场数据编数字 | 无数据就 `[待验证]`，或引用创作者提供的对标 |
| 跳过停靠直接立项 | 除创作者声明"一次跑完"外必须停靠 |
| 简报混入故事设定（人物小传、分集想法） | 故事内容属阶段二；简报只交接事实、空间与约束 |

## 边界

- 不做故事开发、不写大纲剧本、不做分镜、不生成媒体（分别属于下游阶段）。
- 不提供平台实时数据（充值流水、投放成本等）——涉及即 `[待验证]` 并注明需创作者核实。
- 不替创作者做最终立项决定；本技能产出建议与证据。
