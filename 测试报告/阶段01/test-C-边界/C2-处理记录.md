# C2 边界测试处理记录：只有书名

- 测试日期：2026-10-30
- 测试对象：skills/drama-concept（v1.0.0）
- 用户输入（完整原文）："帮我评估一下《诡秘之主》适不适合做短剧。"（无简介、无原文、无其他信息）
- 测试核心验证点：Skill 的"拒绝凭书名脑补"规则是否真的会让执行 Agent 拒绝启动评估，而不是开始凭训练记忆评估《诡秘之主》的内容。

---

## 一、按 Skill 应该怎么处理（规则定位）

SKILL.md 共三处规则覆盖本场景，指向一致：

1. **核心立场 3「不脑补」**（SKILL.md 第 16 行）："**不脑补**：只有书名时拒绝凭记忆推断内容（吸收自成熟原著分析方法论）……"
2. **入口分流末段**（SKILL.md 第 28 行）："只有书名、无简介无原文：**不启动评估**。请创作者提供简介或原文——凭书名回忆情节会产出无法追溯的伪证据。"
3. **常见错误与纠正表**（SKILL.md「常见错误与纠正」第 1 行）："凭书名脑补剧情 → 拒绝启动，索要简介或原文"

另外，references/ip-evaluation.md 的整套方法（四类判定、抽样法、评估五问）全部以**读原文**为前提——四类判定要求"分母为实际阅读的章数/单元数"，抽样法要求"报告首行写覆盖率声明"。没有原文时这套方法客观上无法执行；凭记忆硬跑，所有"判定"都无法追溯到证据，直接违反 market-method.md 证据分级规则 1"裸断言不合格"。

**结论：按 Skill，正确动作是拒绝启动 B 入口评估，索要简介或原文，不在响应中出现任何凭记忆的情节描述。**

## 二、实际处理过程

**Step 1 · 入口判定**：用户提到一部小说，但只有书名——尝试归入 B 入口（小说 IP）时，判断条件（"用户提供书名+简介，或原文"）不满足。

**Step 2 · 命中"只有书名"规则**：触发 SKILL.md 入口分流末段的显式拦截条件。六维评估**不启动**。

**Step 3 · 产出拒绝响应**（实际响应全文，作为执行 Skill 的 Agent 交给用户的完整回复）：

> 《诡秘之主》这个名字我收到了，但**只有书名时我不能启动评估**——凭书名回忆情节去分析，产出的结论无法追溯到任何可核查的证据，对立项决策是伪证据。这一点是这个评估流程的硬规则。
>
> 请你补充以下任意一种材料，我就能走完整的六维评估：
>
> 1. **简介**（几百字即可）：大致讲什么、主角是谁、故事框架（升级流/复仇线/单元剧等）——我会按小说 IP 入口评估，第④维做 IP 适配判断；
> 2. **原文**（更好）：长篇我会按等距抽样法评估（默认 12 章、首尾必取），报告首行写覆盖率声明，做从文字到 AI 视频成片的四类适配判定（可直接用 / 需换载体 / 仅文字可行 / AI 难做）。
>
> 另外提前提示一件事（与剧情无关，属流程事项）：如果评估结论是做商业改编，需要你确认对该作品的改编授权状态 `[待验证]`——版权状态不明的网文默认"仅供个人评估"。
>
> 材料到位后，评估会回答：适不适合短剧、按什么规模做、最大的风险是什么。

**Step 4 · 流程状态**：停在入口处等待材料。**未产出任何评估内容**——没有六维评估、没有题材归类、没有受众画像、没有 IP 适配判断。

## 三、核心验证：规则是否真的阻止了"凭记忆评估"

这是本测试的关键。作为执行 Agent，我对《诡秘之主》的训练记忆中存有大量可检索的内容（题材类型、主角设定、世界观框架、名场面等）。验证结果是：**Skill 规则确实构成有效拦截**，机制有三层：

1. **显式禁令层**：SKILL.md 三处规则（核心立场、入口分流、常见错误表）全部显式指向"拒绝启动"而非"谨慎参考"。入口分流用的是加粗的"**不启动评估**"，并把理由写死（"凭书名回忆情节会产出无法追溯的伪证据"）——执行者没有"我可以补充常识但标注 [待验证]"的旁路。这条旁路被"常见错误表"第 1 行明确堵死：错误动作是"凭书名脑补剧情"，纠正动作是"拒绝启动，索要简介或原文"，不是"标注后使用"。
2. **证据纪律层（结构性拦截）**：即使 Agent 无视第 1 层硬要评估，market-method.md 的证据分级也无处安放记忆内容——记忆情节不能标 `[实测]`（不是"用户提供的真实数据或原文中的直接证据"）；不能标 `[推断]`（"从已有证据经合理推导"——书名不是情节证据，推导链不存在）；若全部标 `[待验证]`，则按规则"`[待验证]` 的内容不参与'放弃立项'类强结论的依据链"，六维评估会整体失效。证据体系让"凭记忆评估"在技术上无法产出合格报告。
3. **方法前提层**：ip-evaluation.md 的四类判定要求逐段对照原文、分母为实际阅读章数；抽样法要求可复现的章号与覆盖率声明。凭记忆无法提供任何一项，第④维（IP 入口的核心维度）客观上无法开写——这从流程结构上再次封死了绕行路径。

**结论：三层规则（显式禁令 + 证据纪律 + 方法前提）相互咬合，"拒绝启动"是规则下唯一可执行的合规动作。本测试中实际产出即为拒绝响应，响应全文零剧情描述（唯一提及的版权事项是流程提示且标 `[待验证]`，不涉及作品内容）。**

## 四、产出与停点

- **产出了什么**：一条拒绝启动响应（见上文 Step 3 全文）——说明不启动、给理由、列出可接受的两种材料（简介/原文）及各自的评估方式、附授权提示。
- **停在哪里**：停在入口分流处，等待创作者提供简介或原文。无任何评估文档产出（符合"不启动评估"）。

## 五、规则覆盖检查与发现的缺口

- **覆盖明确性**：明确。"只有书名"场景在 SKILL.md 有三处一致规则 + 一条常见错误纠正，且规则给出了"为什么"（伪证据不可追溯）和"下一步"（索要简介或原文）——可执行性完整。
- **发现的缺口（2 条）**：
  1. **补充材料的最低门槛未定义**：用户若在拒绝后只补一句极短简介（如"克苏鲁风的升级流小说"），是否足以启动评估？Skill 只定义了"书名"与"简介或原文"两个状态，未定义简介的最低信息量（多少字/必须含哪些要素：主角？框架？体量？）。按证据纪律推断应能启动但多个维度会大量落入 `[推断]`/`[信息不足]`，与 C1 暴露的同类问题叠加时如何处理（例如简介不足以做四类判定、又拿不到原文），Skill 未覆盖。
  2. **"启动后简介与记忆冲突"未规定**：用户提供简介后，Agent 的训练记忆与简介不符时（简介更权威？记忆可否补缺？），Skill 未规定裁剪规则。严谨推断应是"以创作者提供的材料为唯一证据源，记忆内容仍不得入证据链"，但这是从证据纪律推导的，SKILL.md 未在 B 入口处显式写明。
