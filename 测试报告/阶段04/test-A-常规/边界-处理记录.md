## 1. 请求拆解为三个视觉事实

| 事实 | 三层模型判定 | 处理 |
|---|---|---|
| ① 淋雨湿身（现有造型被淋湿） | 身份不变、状态改变（湿污）——**变体，不是新资产**，更不是改卡 | 造型表追加"湿身态"变体 |
| ② 换白T恤（新造型） | 换装——**造型变体** | 新变体 ID 追加（V 顺延） |
| ③ "直接把黑西装卡改了" | 违反修订规则 | **拒绝执行**，走"追加变体"路径 |

## 2. 按规则的正确操作（EP002 剧本确认后执行）

**造型表追加（V1 原样保留，不覆盖、不删除）**：

| 变体 ID | 造型 | 与基础锚点的关系 | 使用集 | 状态 |
|---|---|---|---|---|
| CHAR-1-V1 | （原造型，不动） | — | EP001 | 不变 |
| CHAR-1-V2 | 湿身态：V1 造型淋雨湿透——布料贴身、发梢滴水、面部挂水珠 | 身份锚点不变，新增：湿污状态 | EP002 | 未出图 |
| CHAR-1-V3 | 白色圆领T恤干态（+ 本集下装待剧本确认） | 身份锚点不变，新增：换装造型 | EP002- | 未出图 |

配套动作：
1. **每个变体 = 独立参考图需求**（V2/V3 各一条 IMG，编号顺延；派生视图按需）；
2. **登记表追加两行**（状态"未出图"），V1 行不动；
3. **场景侧评估**：淋雨若发生在室外 → 新 LOC（雨夜街道等）或既有场景的"雨"时段变体——按集拆建，不提前铺；
4. 若剧本确认湿态只存在于换装前一瞬，V2 仍要建（"剧本用到的每个状态都有独立参考图"）。

## 3. "直接改卡"会破坏什么（逐条）

1. **已投产一致性崩**：EP001 全部镜头（含阶段五将冻结的关键帧、阶段六已生成的镜头）引用的是 V1；AI 生成没有"改设定"，只有"换资产"——改卡后新出图与已出图不一致，同一角色前后集肉眼可见跳戏。
2. **违反修订规则**：SKILL 明文"新造型中途加入：新变体 ID 追加（V 顺延），不覆盖旧变体；旧变体在后续集仍可能被引用"——V1 在后续集回闪/同造型戏仍可能复用；删除引用须标"闲置"（备复用），也不能删。
3. **登记表状态机断裂**：静默覆盖不产生"过期"标记 → 依赖 V1 锚点图的派生图（侧面/背面/45°/特写）不会联动过期 → 阶段六已生成镜头进不了返修清单，坏图静默流通。
4. **连续性锁风险**：若"改卡"连基础身份锚点一起动（换脸/换发型），跨集身份锁失效——那等于换了一个演员。

**一句话回复用户**：不能改卡——湿身和白T恤各建一个新变体（V2/V3），各出一张参考图，黑西装 V1 原样保留（EP001 已在用，后续集还可能穿回）。

## 4. 规则覆盖度评估

**覆盖（Skill 现有规则可直接裁决）**：
- 三层模型：湿污明确列为变体示例（"换装/受伤/湿污/时段天气"）→ 事实①有据；
- 修订规则："新造型中途加入：新变体 ID 追加（V 顺延），不覆盖旧变体" → 事实②③有据；
- 登记表状态机 + 重出影响评估 → 破坏后果③有据。

**缺口①（人物状态变体无 ID 约定）**：道具卡模板有"状态变体"表（合上/打开/损坏各有变体 ID），人物卡模板只有"服装造型表"——"同一套衣服的湿/破/染血态"与"换一套衣服"共用 V 序列，语义混叠（V2 是湿了的旧衣服还是新衣服？）。本记录用顺序编号（V2=湿态、V3=新造型）处理；建议 Skill 补人物"造型状态变体"命名约定（如 V1-W 湿态、V1-D 损坏态，与换装变体区分）。

**缺口②（已确认资产的变更入口缺失）**：修订规则只写了"剧本改版→受影响资产版本+1"与"上游矛盾停笔报 DEC"，未写"用户口头要求改已确认资产"的入口——本例靠"新造型中途加入"条款兜住；但若用户要求改的是**已确认的身份锚点**（而非加造型），只能近似套"上游矛盾停笔报 DEC"。建议补一条：已确认资产的非变体级变更（改锚点/改锁面）须走 DEC + 重出影响评估。

**缺口③（示例资产混用无预警）**：示例项目与生产项目共用一套文档格式，Skill 未提示"先核对 project_id 再执行变更"——本记录第 0 步为自加防线。

## 5. 结论

- 请求实质 = 1 个状态变体 + 1 个造型变体，均为**追加**操作；
- "直接改卡"被规则体系三处条款共同否决（修订规则/状态机/一致性原理）；
- Skill 对本边界的裁决能力：主干有据，人物状态变体 ID 与已确认资产变更入口两处需补规则。
