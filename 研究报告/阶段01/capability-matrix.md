## 关键方法论对照（同主题不同实现）

### "值不值得做"判断

| 来源 | 判断结构 | 优势 | 缺口 |
|---|---|---|---|
| novel-analyze 快评 | 六件事固定结构 + 抽样覆盖率 + 回填对照 | 结构化、可证伪 | 仅限已有小说 |
| concept_planning | 六问 + 反模式清单 | 覆盖原创点子 | 非商业视角 |
| develop | 候选七要素 + 机制不同判据 | 方向比较科学 | 不做评估只做开发 |

→ 融合设计：**入口分流**（原创点子 → 六问式评估；小说 IP → 快评式评估）+ **统一结论**（立项六维）。

### "制作负担"评估

| 来源 | 维度 |
|---|---|
| novel-analyze | 同框人数/不重复空间/群戏/动作特效/可读文字/跨时间造型 |
| develop 题材卡 | 压力来源/场面颗粒/制作负担 |
| develop 候选 | "主要制作负担"要素 |

→ 融合设计：统一为 **AI 制作可行性五维**（角色量与一致性难度/场景量与复用度/动作与特效复杂度/数字与文字类画面/时长×镜头量级），并新增"参考图依赖度"维度（AI 视频特有）。

### 输出文档哲学对照

| 仓库 | 哲学 | 对阶段一的启示 |
|---|---|---|
| drama-skills | creator-first 人读 Markdown + 稳定 ID + 机械核对脚本 | 评估报告用固定段落结构 + 结论字段化 |
| shuohao | JSON + 质量门脚本 | 立项数据用 schema 化字段（可校验） |
| seedance-2.0 | 分层门控 + 待验证标注 | 无法确认的市场/模型事实标注"待验证" |

→ 融合设计：**Markdown 人读报告 + 头部 YAML/字段化结论区**（机器可解析），不建复杂数据库。
