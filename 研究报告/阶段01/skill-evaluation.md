## 1. short-drama-novel-analyze（drama-skills）

- **文件路径**：`drama-skills/skills/short-drama-novel-analyze/SKILL.md`（238 行）；关键引用 `references/adaptation-triage.md`（117 行）、`references/adaptation-value.md`（126 行），均已完整阅读。引用文件真实存在且内容与主文档一致（抽查通过）。
- **对应制作阶段**：阶段二为主；其 S1 快评与 S5 改编价值判定是**阶段一最接近"选题评估"的参考实现**。
- **核心功能**：把长篇小说拆成可追溯的原著分析，含"值不值得全量拆解"的快评与"改编价值"终评。
- **工作流程**（与阶段一相关部分）：脚本抽样（确定性、首尾必取、覆盖率写入首行）→ 快评六件事（故事框架/三类判定比例/开篇替换点/制作负担量级/三处最大改编风险/分集候选量级）→ 停靠问创作者 → 全量拆解后回填对照被推翻的判断。
- **输入要求**：原著文件路径（禁止凭书名脑补）；目标制作形态（按形态估负担）。
- **输出内容**：`triage.md` 六段固定结构、`adaptation-value.md`（三类判定/载体替换/制作负担/桥段标签/分集候选）。

### 关键设计优点（含证据）

1. **三类判定体系**（`screen_ready` / `needs_carrier` / `prose_only`，adaptation-value.md L26-33）是"文字→画面"可拍性的精确语言，且明确"不把 prose_only 悄悄改成 needs_carrier——假装的代价会在分镜阶段才暴露"。这是跨阶段风险前置的典范。
2. **抽样诚实性**：快评首行强制写覆盖率（"读了 340 章中的 12 章（3.5%），结论是假设，不是结论"），分母统一为抽样章数；S5 回填对照机制让快评承担"可证伪假设"角色。
3. **制作负担量级评估**（同框人数/不重复空间/群戏/动作特效/可读文字/跨时间造型）——直接可复用为 AI 制作可行性评估维度。
4. **开篇替换点**（L81-95）：第 1 集从哪里开始的具体方法论（收益最强点 + 冷开候选 + 必须后补的信息 + 原著读者需要而短剧观众不需要的），是"开场钩子设计"的最佳参考。
5. **桥段标签种子表**（L62-69）：按题材列出打脸/马甲掉落/废柴逆袭等桥段词表，可扩展不封闭——题材×爽点的结构化知识。
6. **停靠机制**（S1 后 `paused_after_triage`）与"一次跑完时仍写快评"的弹性处理。

### 存在的问题

1. **只评估"改编可行性"，不评估"商业价值"**：六件事没有任何受众、市场、竞争、付费维度——这是拆书 Skill 的定位使然，但对阶段一而言只覆盖一半。
2. 无原创选题入口（必须输入小说）。
3. 快评的集数量级（"约 20-30 集"）没有给出推算依据的格式约定（只有"从 N/M 章推出来"一句）。

### 不适合直接采用的设计

- S0-S5 全管道与 `_work/` 发布生命周期属于阶段二职责，不应并入阶段一 Skill。
- `novel_index.py` 的章节索引逻辑是长篇拆解工具，阶段一不需要。

### 值得吸收的能力

三类判定、快评六件事、抽样诚实性、制作负担量级维度、开篇替换点、桥段标签表、停靠确认机制。

## 2. webnovel-writing / concept_planning 模块（Chinese-WebNovel-Skill）

- **文件路径**：`Chinese-WebNovel-Skill/SKILL.md`（根入口）+ `references/modules/concept_planning/`（README + tutorial 已完整阅读，runtime/good_examples/bad_examples 抽查存在）。仓库另有 10 个模块（opening/volume_outline/plot_logic/chapter_ending/dialogue/anti_ai_voice/consistency_review/character_consistency/transition）与语料库（data/articles/*.txt 10 篇短篇 + demo 目录）。
- **对应制作阶段**：阶段二为主；concept_planning 模块的"选材六问"是阶段一"点子值不值得做"的网文版。
- **核心功能**：中文小说简介 → 规划/起稿/续写/改写；concept_planning 负责点子值不值得写、卖点/引擎判断。
- **工作流程**（选材部分）：六问判断（题材消费点 → 卖点异常局面 → 眼前麻烦 → 故事引擎 → 目标长度 → 最小骨架）→ 输出最小产物（一句话 hook / premise / 主角目标 / 阻力源 / 引擎说明 / 第一卷目标）。
- **输入**：一段小说简介。
- **输出**：最小骨架卡（hook/premise/引擎等）。

### 关键设计优点（含证据）

1. **选材六问**（tutorial.md L13-73）是"点子可开发性"的精炼框架：尤其"读者主要来吃什么（爽点/甜点/刀点）"和"接下来 10-20 章靠什么持续推进（升级/调查/身份反打/关系拉扯/倒计时）"——后者就是短剧"追看引擎"判断。
2. **反模式清单**（L77-99）：设定大事件弱、卖点抽象、主角特别但没被逼着动、hook 像世界观简介——每条都是高频选题错误。
3. **模块化架构**：每模块 README/tutorial/runtime/good_examples/bad_examples/source_index 五件套，统一可扩展（module_template.md）。
4. **语料库支撑**：data/articles 提供真实网文短篇做模仿检索（"先匹配本地语料再写新内容"）。

### 存在的问题

1. **网文读者视角，非短剧商业视角**：无受众画像、无付费卡点、无竖屏时长结构（网文章节逻辑 vs 短剧集卡逻辑不同）。
2. 无市场/竞争分析维度。
3. 仓库无 LICENSE：法律上不可复制其文本，只能借鉴方法论后独立重写。
4. 主 SKILL.md 的流程为"写作会话"设计（判断前置规划→章节循环→完稿审查），选题只是其中一个分支，不是独立可复用的立项流程。

### 不适合直接采用的设计

- 网文正文写作流程（黄金三章、章纲、单章循环）不属于影视选题。
- 以"读者"为中心的表述需改写为"观众/用户"。

### 值得吸收的能力

选材六问（改造为"选题六问"）、反模式清单（改写为短剧版）、"先想能不能立住再谈写"的顺序原则。

### 评分：68/100

| 维度 | 得分 | 依据 |
|---|---:|---|
| 专业知识准确性 | 15/20 | 网文选材方法准确，但缺少短剧/视频媒介适配 |
| 工作流程完整性 | 9/15 | 只覆盖"点子→骨架"一步，无评估报告、无立项闭环 |
| 任务拆解和执行能力 | 10/15 | 六问框架清晰，但无脚本/结构化执行 |

## 3. short-drama-develop（drama-skills）

- **文件路径**：`drama-skills/skills/short-drama-develop/SKILL.md`（163 行，已完整阅读）；`references/genre-cards.md` 为题材卡索引（一次只读一张卡，抽查索引存在）。
- **对应制作阶段**：阶段二为主；"方向探索"与"题材卡"两部分与阶段一的"题材分析与方向选择"相关。
- **核心功能**（相关部分）：把创作者意图变成故事系统；方向未定时提出少量**机制不同**的候选（改变主角策略/对抗来源/代价/持续冲突方式，而非换标题换职业）。
- **输出**：creative-brief.md、story-engine.md、episode-map.jsonl 等（阶段二产物）。

### 关键设计优点（含证据）

1. **"机制不同 vs 伪差异"的判断标准**（SKILL.md L55-58）："方向未定时提出少量机制不同的候选……不为凑选项制造伪差异"——选题阶段区分真方向与换皮的关键判据。
2. **候选七要素**（L59）：戏剧承诺/主角追求/对抗机制/反复回报/可升级状态/长线终止条件/主要制作负担——"每个候选说明……主要制作负担"把制作可行性纳入方向选择，可直接吸收进选题评估。
3. **题材卡设计**（genre-cards.md 索引 + L61-63）：每题材"更常用的压力来源、场面颗粒与制作负担"，可被创作者一句话覆盖——题材知识的正确粒度。
4. **规则分级**（structural_invariant/reviewed_invariant/craft_default/taste_option）防止把配方当门槛。

### 存在的问题

1. **不做商业评估**：候选七要素无受众/市场/成本收益维度。
2. 无立项文档（项目定位、规模、风险）。
3. 题材卡"一次只读一张"的按需加载在选题比较场景（需要横向对比多题材）反而不便。

### 不适合直接采用的设计

- 故事引擎/分集地图/多集整稿接入全部属于阶段二。
- 创作者契约（creator-brief）格式面向故事开发而非立项。

### 值得吸收的能力

机制不同判据、候选七要素（扩展为立项八要素时保留制作负担）、题材卡"压力来源/场面颗粒/制作负担"三字段结构、规则分级思想。

## 阶段一参考总结论

1. **无一个参考 Skill 覆盖阶段一全貌**——最高分（novel-analyze 82）也只覆盖"小说改编价值评估"半壁。阶段一 Skill 必须原创主体，融合四家碎片：
   - novel-analyze 的**评估方法论骨架**（快评六件事→三类判定→制作负担→停靠）；
   - concept_planning 的**点子可开发性判断**（六问 + 反模式）；
   - develop 的**候选比较结构**（机制不同 + 七要素）与题材卡三字段；
   - taxonomy 的 market 阶段定义（选题+IP 评估双入口）。
2. **必须补齐的原创知识域**（无参考可抄）：受众画像（短剧观众分层与观看动机）、市场与竞品分析方法、短剧商业模式（付费卡点/免费投流/分账）、爽点与情绪价值的商业化语言、AI 制作可行性（模型能力 vs 题材需求的匹配）、项目规模/风险/立项书格式。
3. **候选 Skill 数量决策**：阶段一做一个 Skill（`drama-concept`：选题与项目立项），不做多 Skill 拆分——评估、立项、简报三个产物同属一个决策链，拆开会制造不必要的交接。
