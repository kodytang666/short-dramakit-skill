## 原创增量

1. **故事圣经统一格式**（bible.md）：人物档案（CHAR-ID、分档、一句话、小传、目标/筹码/底线、弧光节点、关系、画面代称预留）+ 世界观规则 + 时间线 + 伏笔-兑现登记簿（FORESHADOW-ID：埋设集/兑现集/内容）。
2. **情节节奏表**（rhythm.md）：逐集一行（集号/钩子类型/主要爽点/情绪值 1-5/卡点建议），集数多时分批。
3. **阶段一接口**：接收制作简报的已定事实（不得推翻，冲突时记 DEC 回阶段一）。
4. **连续性设定文档**（continuity.md）：世界观硬规则、时间线、地理、伏笔登记——阶段四的连续性锁从这份文档生长。

## Skill 设计

- 名称：`drama-story`；单 Skill，两个入口（A 从制作简报开发 / B 小说改编，A 又分原创与已有素材）。
- 主流程（B）：原文登记与覆盖率声明 → 索引/提取 → 聚合（故事单元+爽点表）→ **快版骨架（砍线合人爆点）→ 停靠拍板** → 故事引擎 + 圣经 + 细版分集 → 量化自检 → 产出。
- 停靠 2 处：骨架拍板（必停）、成稿确认（可被"一次跑完"豁免，与阶段一一致）。
- 输出：原著分析报告.md（B）/ 故事大纲.md / 故事圣经.md / 分集大纲.md / 情节节奏表.md / 连续性设定.md。
- ID 体系：CHAR-（人物）、PROP-（叙事道具）、LOC-（主场景）、EP-（集）、FORE-（伏笔）、DEC-（决策）。
- 质量门：9 项量化自检清单（角色分档上限、主场景动态上限、爽点间隔 ≤3 集[参数化]、首集钩子、大爆点不压尾集、每集六字段完整、进出状态可交接、伏笔登记完备、引文可溯）。

## 测试方案

- A 常规：从阶段一测试 A 的制作简报（女法医）接收，开发完整故事系统（40 集）。
- B 复杂：用赘婿 IP 前五回做改编（与阶段一测试 B 同 IP，验证跨阶段连续性）。
- C 边界 1：无原著、无简报的裸点子直接开发（阶段一未跑的直通场景）。
- C 边界 2：极短素材（500 字梗概）改编 60 集的处理（体量缺口应对）。
