## 1. short-drama-novel-analyze（drama-skills）—— 88/100

**评估基础**：SKILL.md 全文（238 行）+ adaptation-triage.md + adaptation-value.md 全文；阶段一评估已覆盖其评估方法，此处聚焦其**拆解管道**。

- **阶段映射**：阶段二主（原著分析子流程）。
- **工作流程**：S0 脚本章节索引（中文章号识别、单一编号单位、verify 行号校验）→ S1 快评停靠 → S2 逐章功能提取（并发子代理写 _work/、主线程发布、覆盖率门）→ S3 剧情单元与节奏聚合（故事单元进/出状态、爽点表排名）→ S4 人物归并（跨章去重、别名归一、"归并是候选不是资产"）→ S5 改编价值与分集候选 → 交接 develop。

### 优点（含证据）
1. **S0-S5 每步有停靠条件与产出物**（SKILL.md L56-63 表格），索引脚本"不做编辑判断"与 agent 创作产物分离——确定性工作归脚本、判断归模型，边界干净；
2. 覆盖率门："unmatched_files 不计入覆盖、命名错误的提取文件先更正再补跑"（L154-158）——对抗 agent 常见的"假装完成"；
3. 人物归并的克制："人物归并是候选，不是资产……绕过这条链直接建资产，等于让原著的人物表冒充剧本的出现证据"（L173-181）——跨阶段职责纪律的典范；
4. 并发子代理模式（写 _work/、主线程发布、固定 artifact-id 重发 progress）——长任务工程化；
5. 断点续跑（_progress.md + paused_after_triage）。

### 问题
1. 依赖项目工具链（project_tool.py publish/accept 生命周期），独立运行时降级路径描述存在但复杂；
2. 分集候选 episode-candidates.jsonl 与 develop 的 episode-map.jsonl 存在双份集结构的潜在不同步风险（靠纪律非脚本）；
3. 中文章号识别强，但外文/无章节标记文本回退路径弱（需手写边界）。

**纳入融合方案**：✅ 核心吸收（S0 索引思想、S2 覆盖率门、S3 爽点表与故事单元、S4 归并候选原则、S5 候选集概念）。

## 2. short-drama-develop（drama-skills）—— 91/100

**评估基础**：SKILL.md 全文（163 行）+ episode-design.md 关键节。

- **阶段映射**：阶段二主（核心 Skill）。
- **工作流程**：锁定创作者契约 → 方向探索（机制不同候选+七要素）→ 故事引擎（压力/反制/每轮改变什么/终止条件）→ 分集地图（episode-map.jsonl：进入状态/开场/当集追求/阻力/转折/结果/信息释放/出去压力/交接事实）→ 所有者自检 → 交接。

### 优点（含证据）
1. **故事引擎六问**（SKILL.md L70-77：压力如何出现/对手如何反制/每轮冲突改变什么/人物目标筹码底线/何种转变终结引擎/视觉声音边界）——"持续制造选择、代价与状态变化"的系统化表述，是防"越写越薄"的核心工具；
2. **episode-design 单集契约**（episode-design.md L18-30）：可验证进入状态→当集压力→选择遭遇反制→部分回报→新压力→可验证出去状态——"一集为什么必须在这里发生"的因果定义；钩子七形态（L60-69）把"未稳定局面"具象化；
3. **因果升级链**（L90-96）："因为 A，人物采取 B；B 触发反制 C；C 改变状态 D，迫使放弃旧策略"——反"预填冲突次数"；
4. 首集入口"收益入口 vs 冷开"比较 + 改编项目"高光排到观众最早能拿到的位置"；
5. 前史储备不倒进首集对白（serial-character）；
6. 按需加载 14 个 references 且入口判断先行（5 种入口，L28-38）。

### 问题
1. 无量化质量门（与 shuohao 相反），升级是否真实靠 reviewer 语义判断——质量波动风险；
2. episode-map.jsonl 字段多（9 字段/集），60 集以上项目的填写成本高，无分批策略说明；
3. 改编映射 adaptation-map.jsonl 与 novel-analyze 候选集的对接靠人工，无机械校验。

**纳入融合方案**：✅ 核心吸收（故事引擎六问、单集契约、钩子形态、因果升级链、收益入口vs冷开）。

## 3. novel-outline（shuohao-skills）—— 90/100

**评估基础**：SKILL.md 全文（177 行）+ outline-pass.md 全文。

- **阶段映射**：阶段二主（小说→大纲五件套）。
- **工作流程**：收参数（集数×时长×题材三必问）→ 定位输入（禁止凭书名脑补）→ 分卷摘要（长文并发子代理）→ 快版骨架四块 → **用户拍板砍线/合人/大爆点** → 细版骨架 → 分批分集梗概（≤10 集/批）→ 14 道质量门校验 → 渲染报告。

### 优点（含证据）
1. **五步改编顺序即方法论**（outline-pass.md）：砍线→合人→收场景→排爽点→收道具，且每步给出理由——"道具排在爽点之后不是随便排的：叙事道具的判据是它托起哪个爽点"；道具判据一句话（"它坏了丢了被换掉，剧情会不会塌"）；
2. **14 道量化质量门**：主角组 ≤5、重要配角 ≤10、主场景上限随集数动态（4+⌈集数/10⌉ 夹 5-15）、爽点间隔 ≤3 集、第 1 集有钩子、大爆点不压最后一集、三人同框有拆解、叙述体无对白——**可执行可校验的硬约束**；
3. **两轮拍板制**：快版骨架先过 beats 档就停下拍板（"快版错了只损失一轮骨架，分集写完才发现方向错，全废"）——成本控制的分险设计；
4. 联动更新靠校验器不靠记忆（"合并人物后哪些集还引用被删 ID"）；
5. 阈值参数化（params.thresholds 覆盖，"阈值是参数不是圣旨"）。

### 问题
1. 无故事引擎/单集契约层（梗概是叙述体，因果密度低于 develop 的 episode-map）；
2. 原著分析深度弱于 novel-analyze（无逐章功能提取、无三类判定）；
3. 质量门部分为题材无关的经验值（爽点间隔 ≤3 集对悬疑单元剧可能偏紧）。

**纳入融合方案**：✅ 核心吸收（五步改编顺序、量化质量门体系、两轮拍板、联动校验思想；阈值按题材放宽）。

## 4. novel-characters（shuohao-skills）—— 84/100

**评估基础**：SKILL.md 工作流（Step 0-3）+ frontmatter。

- **阶段映射**：阶段二主（人物侧）+ 阶段四次（形象提示词）。
- **工作流程**：seed（吃 outline 人物清单，分档不推翻）→ 分块读原文 → 角色表/画像/形象提示词/音色提示词 → 校验（引文逐字比对原文）→ 报告。

### 优点（含证据）
1. **seed 机制**：大纲定的分档不推翻——"真觉得分档不对，回去改大纲，别在这里悄悄改一个不一样的"——上游权威纪律；
2. 引文逐字校验（需原文文件比对）——人物判断可追溯；
3. 角色码 id 贯穿 script/storyboard——ID 稳定性设计；
4. 重要度三档映射（lead→protagonist 等）。

### 问题
1. 人物深挖（弧光/压力测试/前史）弱于 develop 的 serial-character；
2. 音色提示词属阶段四/六职责，阶段二做略早（但为 TTS 提前锁定音色有其道理）。

**纳入融合方案**：✅ 部分吸收（ID 贯穿、seed 上游权威、引文追溯）。
