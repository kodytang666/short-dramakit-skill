# 阶段三参考 Skill 逐个评估

## 1. short-drama-write（drama-skills）—— 90/100

- **评估基础**：SKILL.md 全文。
- **工作流程**：入口判断（分集规划/裸大纲/已有剧本/非规范文本）→ 工作流 8 步（锁定本集承诺→识别看点机制→排因果节拍→逐场确定功能→写入剧本→静默反查→局部修订）。
- **优点（含证据）**：
  1. **可拍性语法**：场景标题 `## EP001-SC001 内 · 地点 · 时间/天气`；对白 `角色（可选表演提示）：台词`；生产标签 `[VO][OS][SFX][画面文字][连续性][转场]`——一套完整的、下游（分镜/剪辑）可机械识别的剧本方言；
  2. **"每场改变信息、权力、关系、情绪、物理状态或风险；无变化的场删掉或合并"**——场次存废的因果判据；
  3. 对白功能论："对白必须在争取、回避、试探、逼迫或重新定义关系"；
  4. **静默反查**：交稿前只读剧本自查（观众能否接收到承诺/因果是否成立/语气一致），自检增添的机关撤去——防 AI 过度发挥；
  5. "转不成演员一个动作或表情的句子删掉或改成动作"——台词可演性检验；
  6. `[连续性]` 只交接易丢失状态，不证明镜头外未发生的事；
  7. 时长"通读压稿"优先于数字估算（估算是参考不是门禁）。
- **问题**：无量化门（时长/句长无下限卡位）；台词无结构化字段（TTS 需二次解析）；无分批策略（长集跨上下文处理靠 scene-handoff 摘要）。
- **纳入**：✅ 核心（剧本方言、场次判据、对白功能论、静默反查、可演性检验）。

## 2. novel-script（shuohao-skills）—— 89/100

- **评估基础**：SKILL.md 全文。
- **工作流程**：seed 骨架（搬运事实不让模型重想）→ 逐集写戏（一批 ≤3 集）→ 10 道门校验 → 渲染报告（时长仪表/场次总表/台词本聚合）。
- **优点（含证据）**：
  1. **节拍流**：动作节拍与台词行交替，台词结构化条目（说话人+台词+语气）——TTS 直喂、动作即画面清单；
  2. **10 道量化门**：时长 ±15%（4.5 字/秒、2.5 秒/拍）、单句 ≤35 字、说话人合法、钩子悬念落纸、**钩子具象在前 3 拍内兑现**（hookBeat 认领）、每场至少一个动作节拍（"纯对白的场是广播剧"）、动作不混引号台词、爽点认领、角色对账、场景对账；
  3. **动作节拍只写常见动作**（"挑担上船、搭手卸担这种 AI 见过千万次的；伸篙一挡、睫毛颤这种精巧动作生成必崩"）——阶段三就开始为阶段六把关的 AI 可生成性意识；
  4. 爽点认领门："大纲说这集有大爆点，剧本必须有戏认领它"——防止改编改丢爆点；
  5. seed 上游权威 + 前集结尾悬念交接。
- **问题**：JSON 载体对创作者不友好（需渲染）；时间预算参数（4.5 字/秒）偏经验值但已参数化；散文感弱于 write。
- **纳入**：✅ 核心（量化门全套、节拍流纪律、常见动作原则、爽点认领、分批制）。

## 3. webnovel-writing 对白/去 AI 味模块 —— 70/100

- **优点**：对白专项（谁的话像谁）、anti_ai_voice（去 AI 味：删解释性对白、删总结复述）；模块五件套架构。
- **问题**：网文对白是"读"的对白，短剧对白是"说"的对白（需口语化、一口气原则）；无 LICENSE。
- **纳入**：◐ 借鉴去 AI 味清单思想（写成短剧版自检），独立表述。

## 融合结论

阶段三 Skill（`drama-script`）= write 的**人读 Markdown 剧本方言** + novel-script 的**量化门与节拍纪律** + 网文的**去 AI 味自检**。输出：分集剧本（Markdown，SC/生产标签体系）+ 场次表 + 台词本（按角色聚合，TTS 接口）+ 时长预算表。10 项量化门由 agent 执行自检（无脚本依赖）。
