# 阶段一设计方案：drama-concept（选题与项目立项）

## 1. Skill 架构

```
skills/drama-concept/
├── SKILL.md                        # 主文档：入口分流、评估流程、停靠、输出规范
├── references/
│   ├── genre-cards.md              # 题材速查卡（10 个主力题材，六字段结构）
│   ├── ip-evaluation.md            # 小说 IP 适配评估（三类判定+ai_hard、抽样法）
│   ├── market-method.md            # 受众画像与市场评估方法（证据强度体系）
│   └── ai-feasibility.md           # AI 制作可行性五维评估法
├── templates/
│   ├── topic-report.md             # 选题评估报告模板（六维）
│   ├── project-charter.md         # 项目立项书模板
│   └── production-brief.md         # 制作简报模板（→阶段二接口）
└── examples/
    └── example-选题评估报告.md      # 一个完整示例（战神归来类题材）
```

设计原则：
- **单 Skill**：评估→立项→简报是一个决策链，不拆分。
- **按需加载**：SKILL.md 只写流程与判断标准，专业知识放 references，模板放 templates。
- **人读为主 + 字段化结论**：报告是 Markdown，但每维结论有固定字段行（`结论：`/`证据：`/`强度：`），下游可引用。
- **诚实标注体系**：`[实测]`（用户提供的真实数据/原文证据）`[推断]`（从证据合理推导）`[待验证]`（行业通识但无法核实）三级证据强度。

## 2. 任务流程（主流程）

```
入口分流
├─ A 原创点子入口：一段创意描述
├─ B 小说 IP 入口：书名+简介 或 原文（路径/粘贴）
└─ C 已有评估续跑：读取已有报告，从断点继续

统一流程：
1. 信息采集（一次性问全缺失的必要参数；禁止轮流盘问）
   - 必要：目标平台倾向（付费/免费/未定）、集数×单集时长（或由 Skill 建议后确认）
   - 可选：预算量级、对标作品、创作者不可改约束
2. 题材定位与题材卡匹配（读 genre-cards.md，一次可横向对比 2-3 张卡——选题场景与 develop 的单卡加载不同）
3. 六维评估（每维：结论+证据+强度）
   ① 题材定位：题材/桥段/同质化程度
   ② 受众与市场：受众画像卡（人群/动机/弃点）
   ③ 爽点与情绪价值：爽点类型×密度潜力×开场钩子潜力
   ④ IP 适配（A 入口改为：原创可开发性六问）/商业潜力（B 入口必做三类判定）
   ⑤ AI 制作可行性：五维评估（角色一致性/场景复用/动作特效/画面文字/镜头量级）
   ⑥ 规模与风险：集数×时长×镜头量级、风险登记
4. 候选比较（多候选时）：机制不同的候选对比表（八要素）
5. 停靠：向创作者汇报评估结论 + 建议（立项/放弃/调整后立项），等待确认
6. 立项：写立项书（含决策记录）+ 制作简报（阶段二接口）
```

## 3. 输入规范

| 入口 | 必要输入 | 可选输入 |
|---|---|---|
| A 原创点子 | 一段点子描述（≥1 句，含主角/冲突/卖点中至少一项） | 目标平台、集数时长、预算、对标、约束 |
| B 小说 IP | 书名+简介，或原文（≤全本；长篇可抽样，按 ip-evaluation.md） | 同上 |
| C 续跑 | 已有选题评估报告路径 | 补充信息 |

异常处理：
- 点子只有一句话且无法判断卖点 → 先问一次补充，仍不足则按最可能方向给出 2 个机制不同的候选让创作者选。
- 只有书名无简介无原文 → **拒绝凭书名脑补**（吸收自 novel-analyze），要求提供简介或原文。
- 原文过长 → 按 ip-evaluation.md 抽样法（首尾必取+等距），报告首行写覆盖率。

## 4. 输出规范

### 4.1 选题评估报告（topic-report.md）
- 头部：project_id / date / 入口类型 / 覆盖率声明（IP 入口必写）
- 六维评估，每维固定三行字段：`结论：` `证据：` `强度：[实测|推断|待验证]`
- 候选比较表（多候选时）
- 总评：立项建议（立项/调整后立项/放弃）+ 一句话理由

### 4.2 项目立项书（project-charter.md）
- 项目定位一句话（谁+异常局面+必须做什么+最抓人的点）
- 受众画像卡、核心卖点（≤3 条，每条绑定一个爽点类型）
- 规模参数：集数×单集时长×预估总镜头量级
- 商业模式初判（标注待验证）
- 风险登记表（RSK-编号：风险/类型(商业|制作|内容)/影响/缓解）≥3 条
- 决策记录（DEC-编号：决策/理由/日期）
- 审批区（创作者确认状态）

### 4.3 制作简报（production-brief.md）→ 阶段二接口
- 已定事实（不可改）、可探索空间、边界约束（内容尺度/时长/成本）
- 题材卡要点、受众与爽点要点、制作可行性预警（交阶段四五六提前规避）
- project_id 与版本号

## 5. 质量控制机制

自检清单（成稿前逐条核对，不通过不交付）：
1. 六维齐全且每维三行字段完整；
2. IP 入口必含四类判定比例（含 ai_hard）与分母；
3. 所有市场/平台类论断带强度标注，无裸断言；
4. 风险 ≥3 且覆盖制作+商业两类；
5. 立项书与评估报告结论一致（评估说"调整后立项"，立项书必须体现调整）；
6. 简报三区分离（已定/可探索/约束）无内容互相矛盾；
7. 无编造数据：未获得的平台数据一律 `[待验证]`。

## 6. 异常处理规则

| 情形 | 处理 |
|---|---|
| 创作者中途改变方向 | 记 DEC 决策，重跑受影响维度，报告标注"v2 修订于变更" |
| 评估结论为放弃 | 不写立项书；写简短放弃报告（结论+理由+何种条件下可重启） |
| 长篇原文抽样后创作者提供全本 | 更新覆盖率声明，重跑 IP 适配维 |
| 多个点子混合 | 拆成多个 CAND 候选分别评估，比较表呈现 |
| 创作者跳过评估直接要立项书 | 按最快路径做轻量评估（六维各一句话版），标注"轻量评估" |

## 7. 测试方案

- **A 常规任务**：给定一个完整原创点子（战神归来+赘婿混合题材，含平台倾向与集数时长），验证全流程产出三份文档。
- **B 复杂任务**：给定长篇小说简介+前 5 章（多线都市文），验证 IP 入口、抽样、四类判定、机制不同候选比较。
- **C 边界任务 1**：只有一句话点子（"一个外卖员发现自己是豪门继承人"），验证信息不足路径。
- **D 边界任务 2**：只有书名（无简介无原文），验证拒绝脑补规则。
- **对照测试**：C 任务分别用裸模型（无 Skill）与新 Skill 执行，比较输出的结构完整性、专业维度覆盖、可执行性。
- **静态检查**：frontmatter 合法、引用文件存在、模板字段完整、无互相冲突指令。

## 8. 与其他阶段的接口

- 上游：无（流水线起点）。
- 下游（阶段二）：制作简报是唯一交接文档；project_id 全流水线复用；题材卡 GEN-编号供阶段二题材深化。
- 修改传播：立项书中的规模参数（集数×时长）变更 → 简报版本号+1，下游以最新简报为准。
