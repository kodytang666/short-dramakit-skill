# 阶段二设计方案：drama-story（故事开发与小说改编）

## 架构

```
skills/drama-story/
├── SKILL.md                      # 入口、双流程（A 开发 / B 改编）、停靠、产出规范
├── references/
│   ├── adaptation.md             # 五步改编法（砍线/合人/收场景/排爽点/收道具）+ 覆盖率纪律
│   ├── story-engine.md           # 故事引擎六问 + 钩子七形态 + 收益入口vs冷开 + 单集契约
│   └── quality-gates.md          # 9 项量化自检门（阈值参数化）
├── templates/
│   ├── source-analysis.md        # 原著分析报告（B 入口）
│   ├── story-outline.md          # 故事大纲
│   ├── story-bible.md            # 故事圣经（人物/世界观/时间线/伏笔簿）
│   ├── episode-map.md            # 分集大纲（单集六字段 + 三栏）
│   ├── rhythm-table.md           # 情节节奏表
│   └── continuity.md             # 连续性设定文档
└── examples/
    └── example-分集大纲.md        # 前 3 集完整示例
```

## 主流程

```
入口：A-已有制作简报（阶段一产出）/ A2-裸点子（无阶段一，补轻量约束） / B-小说改编 / C-续跑
B 入口：原文登记（覆盖率声明）→ 功能提取（逐章/逐单元）→ 聚合（故事单元+爽点表）
      → 快版骨架（砍线/合人/大爆点）→ ⛔停靠1：骨架拍板
A 入口：约束确认 → 快版骨架（主线/对抗/大爆点）→ ⛔停靠1
共同：故事引擎 → 故事圣经 → 分集大纲（分批）→ 节奏表 → 连续性设定 → 量化自检 → ⛔停靠2：成稿确认
```

## 接口

- 上游：制作简报（production-brief）；已定事实不得推翻，冲突回阶段一记 DEC。
- 下游（阶段三）：分集大纲单集六字段 + 故事圣经是剧本的输入；CHAR/PROP/LOC/EP/FORE ID 贯穿。
- 修改传播：分集改动 → 同步节奏表与伏笔簿版本。

## 质量控制

9 项量化门（见 quality-gates.md）+ 语义自检（因果链完整性）+ 2 停靠。

## 异常处理

体量缺口（素材撑不起目标集数）→ 停靠给方案（降集数/扩写支线标注 add）；素材超体量 → 建议砍线清单；无章节标记 → 语义分段登记；上游冲突 → DEC 回溯。

## 测试方案

与 design-decisions.md 一致（A/B/C1/C2 + 基线对照），测试报告落 `测试报告/阶段02/`。
